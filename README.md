# 连六棋（Connect Six）

一个使用 **C++17 + EasyX** 编写的 Windows 桌面棋类游戏，支持**双人对战、人机对战、局域网对战**三种模式。棋盘 19×19，黑棋先行：开局第一回合黑棋只落 1 子，之后双方每回合各落 2 子，先连成 6 子（横 / 竖 / 斜，含 6 子以上）者获胜。

> 项目名 / 解决方案：**ifdream-s-games**（工程文件 `ifdream-s-games.vcxproj`）。
> 构建状态：Debug / Release x64 均可编译通过（Visual Studio 2022，v143 工具集，C++17）。
> 最近一次改动：局域网默认端口改为 46888；图片资源统一到 `assets/` 并在构建时复制到输出目录、改为按 exe 路径加载；项目更名为 ifdream-s-games；局域网模块按「大厅 / 对局会话 / 共享界面」拆分。

## 功能特性

- **双人对战**：同一台电脑上黑白双方轮流落子；对局中可悔棋，也可随时「退出」并选择继续游戏 / 返回主菜单 / 退出游戏。
- **人机对战**：内置棋形评估 + 三层递归搜索的 AI；对局中可悔棋，也可随时「退出」并选择继续游戏 / 返回主菜单 / 退出游戏。
- **局域网对战**：TCP 直连（默认端口 46888，避开 8888 等常见端口冲突），主机执黑；支持落子同步、悔棋协商、再来一局协商、随时退出（Esc 或按钮）。
- **通用能力**：悔棋、胜负/和棋判定、对局结束后重新开始或返回菜单、全程鼠标操作。

## 游戏规则

| 项目 | 规则 |
| --- | --- |
| 棋盘 | 19×19 交叉点 |
| 先手 | 黑棋 |
| 每回合落子数 | 通常 2 子；仅开局黑棋第一回合落 1 子 |
| 胜负 | 横、竖、斜任意方向连成 6 子或以上即获胜 |
| 和棋 | 棋盘下满仍无人连成 6 子 |

## 运行环境

- Windows 10 / 11
- Visual Studio 2022（「使用 C++ 的桌面开发」工作负载，v143 工具集，Windows 10 SDK）
- [EasyX](https://easyx.cn) 图形库（建议 2025 版或更新版本）：
  - 头文件安装到 VS 的 `VC\Auxiliary\VS\include`（提供 `graphics.h`、`easyx.h`）
  - 库文件安装到对应平台的 `VC\Auxiliary\VS\lib`（工程为 Unicode 字符集，`easyx.h` 会自动链接 `EasyXw.lib`）

工程同时保留 x64 与 Win32 配置；建议使用 **x64**（已按 x64 完成编译验证）。

## 构建与运行

1. 使用 Visual Studio 打开 `ifdream-s-games.sln`。
2. 选择 `Debug | x64` 或 `Release | x64`。
3. 生成解决方案（F7）或直接调试运行（F5）。

生成产物：

- `x64\Debug\ifdream-s-games.exe`
- `x64\Release\ifdream-s-games.exe`

**资源说明**：图片统一放在仓库根目录的 `assets/` 下，构建时由 `CopyAssets` 目标自动复制到 `$(OutDir)assets\`；程序通过可执行文件所在目录定位资源（`ui/Assets.cpp` 中的 `AssetPath`），因此从任意工作目录启动 exe 都能正常加载图片。

工程为 Console 子系统，运行时会同时出现一个控制台窗口（输出落子/悔棋日志），属正常现象。

## 操作说明

- **主菜单**：鼠标点击「双人对战 / 人机对战 / 局域网对战 / 退出游戏」。
- **对局中**：点击棋盘交叉点落子；右侧下方「悔棋」，其下方「退出」（双人 / 人机模式）。
- **悔棋**：需在回合结束后点击（未完成本回合时点击会提示「完成本回合后方可悔棋」）；人机会回退最近一轮玩家与 AI 的落子，双人会回退最近一轮双方的落子。
- **对局中退出（双人 / 人机）**：点击「退出」弹出确认框，可选择「继续游戏 / 返回主菜单 / 退出游戏」。
- **对局结束**：可在右侧选择「重新开始 / 返回菜单」；双人 / 人机模式此时点击「退出」可直接关闭游戏。
- **局域网对战**：
  - 主机点击「创建房间」，界面显示本机 IPv4 地址，等待对方加入；
  - 客户端点击「加入房间」，输入主机 IP（回车连接、Esc 返回）；
  - 对局中按 Esc 或点击「退出」离开对局；
  - 悔棋需要对方同意；对局结束后可发起「再来一局」协商。

## 架构设计

### 分层与依赖

```text
main.cpp
  ├─▶ ui/      界面与绘制（菜单、棋盘、对话框、按钮）
  ├─▶ modes/   对局流程（人机 / 双人 / 局域网）
  │     ├─▶ ai/     棋形评估 + 递归搜索
  │     └─▶ net/    协议 + TCP 传输 + 在线对局核心（LanMode 专用）
  └─▶ core/    本地棋盘状态 + 规则（只依赖标准库）
```

依赖约束：

- `core/`：只依赖 C++ 标准库，负责棋盘状态、落子合法性、悔棋、胜负与棋形。
- `ai/`：只依赖 `core/`（读取棋盘、调用棋形工具），不依赖界面。
- `ui/`：依赖 `core/` 的棋盘状态与 EasyX，不依赖 AI 和具体模式。
- `modes/`：依赖 `core/`、`ai/`、`ui/`；`LanMode` 额外依赖 `net/`。
- `net/`：协议、TCP 传输与在线对局核心，完全不依赖 EasyX/界面，也不依赖本地 `core/`，具备独立测试条件。
- `main.cpp`：只依赖 `ui/Menu` 与 `modes/`，负责入口与模式分发。

### 本地对局数据流

1. `main()` 加载资源并进入主循环，`MainMenu()` 返回模式编号。
2. 进入对应模式（如 `PVCWindow()` / `PVPWindow()`），循环执行：
   - 用 `GetMouseMsg()` 阻塞等待鼠标事件；
   - 判断是落子、悔棋还是退出；
   - 落子后更新 `core` 的棋盘与落子记录，调用 `checkWin()` 判断胜负；
   - 调用 `DrawBoard()` 重绘棋盘。
3. 人机模式在玩家回合结束后调用 `aiput()` 计算 AI 本回合的 2 步落子。
4. 对局结束调用 `GameEndButtons()`；人机模式退出时返回 `LeaveMatch`，由 `main()` 决定回菜单还是结束程序。

本地模式（双人/人机）的阶段一重构保持了原有的全局棋盘状态（`core/GameState.h` 集中声明），后续可进一步改为显式的 `GameSession` 对象传递，消除全局可变状态。

### 状态管理策略

- 本地模式：`board`、`moveHistory` 等由 `core/GameState.h` 统一 `extern` 声明，各模块共享；这是「先拆文件、后改结构」的低风险阶段方案。
- 在线模式：`LanMode` 持有独立的 `obgame::Game` 实例，不触碰本地全局棋盘，天然与本地模式隔离。

## AI 设计

人机 AI 分两层：

1. **局面评估（`ai/Evaluator.*`）**
   - 对每个空位模拟落下一子；
   - 取该点横、竖、两条斜线共 8 个方向、每方向 7 格的窗口；
   - 用 `getPattern()` 归一化成棋形串，再查棋形评分表。
   - 评分表覆盖 AI 进攻棋形（六连、五连、活四、冲四、活三、活二等）、玩家进攻棋形（负分表示对玩家的价值）以及 AI 防守棋形（阻挡玩家活三/活四等）。

2. **递归搜索（`ai/Search.*`）**
   - 对当前局面取评分最高的 `TOP_N = 5` 个候选点；
   - 以 `dep = 3` 的深度递归，按「AI 回合 / 玩家回合」交替评估，组合当前得分与子树得分；
   - `aiput()` 一次计算 AI 一个回合的 2 子：先算第 1 子，模拟落子后再算第 2 子。

> 性能说明：搜索为同步计算，AI 思考期间主线程不处理窗口消息（界面会短暂无响应），这是当前实现的已知限制。

## 局域网对战设计

### 通信协议

- 传输层：TCP；每条消息固定 **8 字节**（小端）：

| 字节 | 字段 | 说明 |
| --- | --- | --- |
| 0 | `type` | 消息类型 |
| 1–2 | `arg0` | int16，落子 x / 回滚目标历史长度 |
| 3–4 | `arg1` | int16，落子 y / 角色 |
| 5–6 | `arg2` | uint16，预留 |
| 7 | 预留 | 固定 0 |

- 消息类型：`Hello`、`Move`、`UndoRequest/Accept/Deny`、`RestartRequest/Accept/Deny`、`Bye`、`Ping/Pong`。
- 常量：端口 `46888`、协议版本 `1`、棋盘 19×19。

### 连接与对局流程

1. 主机监听 46888 端口，界面显示本机 IPv4 列表；客户端输入主机 IP 连接。
2. 双方互发 `Hello`（协议版本 + 角色：1 主机 / 2 客户端），5 秒内完成握手；主机执黑。
3. 握手成功后启动接收线程，主线程进入对局循环：非阻塞取消息 → 处理网络事件 → 处理鼠标/键盘事件 → 有变化时重绘。
4. 对局中：
   - 落子前校验轮次、是否为空位、本回合剩余子数；非法落子或状态不一致时发送 `Bye` 并断开；
   - 悔棋走「请求 → 同意/拒绝」流程，同意后双方回滚到同一历史长度；
   - 对局结束后可发起「再来一局」协商；
   - Esc 或「退出」发送 `Bye` 并返回大厅。
5. 传输层 `NetChannel`：监听/接受、连接、后台接收线程、线程安全消息队列、发送互斥、`Close()` 幂等；对局核心 `obgame::Game` 两端共用，保证棋盘状态一致。

## 渲染与资源

- 窗口 808×608；棋盘区域 608×608（19×19，每格 32px），右侧 200px 为状态栏与按钮区。
- 绘制方式：先把背景和棋子画到内存 `IMAGE buffer`，再一次性 `putimage` 到窗口，减少闪烁。
- 棋子与背景 PNG 通过 `AlphaBlend` 做透明绘制。
- 图片资源：`assets/black.png`（黑子）、`assets/white.png`（白子）、`assets/menu.png`（主菜单背景）、`assets/board.png`（棋盘背景）；`docs/design/` 为早期设计素材，代码未引用。

## 开发约定

- 源文件统一使用 **UTF-8 with BOM**，避免中文注释在 Visual Studio 中乱码。
- 头文件搜索路径：`$(ProjectDir)src`（`#include "core/GameState.h"` 这类写法）。
- 局域网模块使用 `obnet` / `obgame` 命名空间；本地模块暂不使用命名空间。
- `net/` 与 `core/` 不依赖 EasyX，新增可测试逻辑优先放到这两层。
- 工程包含 `ifdream-s-games.vcxproj.filters`；新增/移动源文件时同步补充过滤规则，解决方案资源管理器才会继续按目录分组。
- 图片资源统一放在 `assets/`，构建时由 `CopyAssets` 目标复制到输出目录；新增资源需同步加入工程（`None` 项）与过滤器（`assets` 分组）。

## 已知限制与后续计划

- **规则实现有两份**：本地模式使用 `core/` 的规则，局域网使用 `net/OnlineGame`；本地落子数由界面流程控制，在线模式由 `obgame::Game` 统一校验。后续可把本地模式也切到统一的对局核心（重构方案 C）。
- **AI 同步阻塞**：思考期间窗口不响应，退出/悔棋要等 AI 落完。
- **无自动化测试与 CI**；`core/`、`net/` 不依赖 EasyX，具备单元测试条件。

## 常见问题

| 问题 | 排查方向 |
| --- | --- |
| 启动后窗口黑屏 / 背景缺失 | 确认 exe 同目录存在 `assets/`（重新生成解决方案会自动复制；手动拷贝 exe 时需连同 `assets/` 一起复制） |

| 中文字体显示异常 | 系统缺少「隶书 / 微软雅黑」字体，可替换为系统已有字体 |
